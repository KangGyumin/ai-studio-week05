# 과제 1 — 하드코딩 키 리팩터링 실습

## 1. 무엇이 위험했는지
API 키와 데이터베이스 접속 비밀번호가 `legacy_report.py` 소스코드에 문자열로 직접 작성되어 있음. 이 상태로 코드가 공개 저장소에 커밋되면, 크롤링 봇이 키 패턴을 탐지하여 수 분 내로 수집함. 수집된 키는 대량 호출에 사용되어 과금 폭탄을 유발하거나, 내부 데이터베이스 유출 등 보안 사고로 직결됨.

## 2. 어떻게 고쳤는지
비밀 값(API 키, DB_URL)을 코드 외부의 별도 파일인 `.env`로 분리함. 그 후 `python-dotenv` 라이브러리의 `load_dotenv()`를 사용해 실행 시점에 환경 변수로 불러오도록 코드를 수정함. `.env` 파일이 Git 추적 대상에 포함되지 않도록 `.gitignore` 파일에 제외 규칙으로 등록하여 물리적으로 격리함.

## 3. 만약 실키가 1차 커밋으로 노출되었다면 올바른 대응 절차는 무엇인지
해당 줄을 지우고 다시 커밋하는 것은 과거 커밋 이력이나 이미 수집된 크롤러 데이터에는 유효한 키가 그대로 남아있기 때문에 잘못된 대응임. 즉시 노출된 키를 폐기하고 새로운 키를 재발급받는 것이 올바른 대응임.
